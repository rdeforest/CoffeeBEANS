## The constraint that shapes everything

**One suite at a time.** Nobody has measured whether two suites can share
the machine without the frame-timing checks failing, so every run takes a
shared lock, in the main checkout because `tmp/` is per worktree:

    mkdir -p /mnt/nvme0n1p4/git/github/rdeforest/CoffeeBEANS/tmp
    flock /mnt/nvme0n1p4/git/github/rdeforest/CoffeeBEANS/tmp/suite.lock \
      npm test > tmp/suite-<track>.log 2>&1

Single parts (`BEANS_TESTS=...`) take the lock too. Never pipe the suite
into `head` (AGENTS.md says why).

**Tracks own files.** A chunk that needs another track's file stops and
says so, and that piece waits for the merge. Shared files have narrow rules:

- `test/suite.coffee` -- any track may add its part's name to `PARTS`.
- `src/renderer/help.coffee` and `README.md` -- K owns them; R and P only
  add their own new entries.
- `src/renderer/renderer.coffee` -- split by section below.

### Needs Robert first

1. **Pause-on-error: the research is in; the decision is yours.**
   `docs/research/pause-on-error.md`. Running the sketch as an event listener
   with no `catch` above it makes `pauseOnExceptions: 'uncaught'` exact, with
   the frame live (measured in the app). The price is arming the debugger
   for every run (Run about 0-50ms slower, caught throws 8-45% slower,
   nothing else measurably slower), and a `breakpoint` left in a sketch would
   then always stop. A skeptical review found the thing the note first
   missed: once armed, errors thrown *outside* the run (timers, promise
   callbacks, after an `await`) pause too, and some of them silently -- that
   must be designed before it ships. Questions for you are at the end of the
   note.
2. **Two data-loss bugs were found and are NOT fixed** (both traced from the
   code, neither run):
   - `openSketch` tests `name in beans.list()` case-sensitively, so on a
     case-insensitive filesystem (Mac, Windows) `:e Foo` with `foo.coffee`
     present writes `''` over `foo.coffee`.
   - Nothing flushes a pending autosave on unload: View > Reload (and Ctrl-r
     from the canvas or the pane) loses an edit made in the last 250ms.
     Ctrl-r *in the editor* is now claimed so it no longer reloads (see
     Decided); the menu path is still open.
3. **Every Run over a running sketch left the old worker running for 2s**
   (H2, found and fixed tonight; now in AGENTS.md). Cause:
   Chromium's `Worker.terminate()` only forces termination after 2 seconds
   (`kForcibleTerminationDelay`), and the zombie shares the frame handshake,
   the print ring and the prompt's question slot. Measured: the old sketch
   printed for 2.0s after Run and took half the new one's frames.
4. **One seam bug reached `main` and was fixed the same night:** a line
   typed at the prompt could be silently withdrawn as if it were a Tab's
   question (P2 x the paused-frame Tab). Worth knowing that four tracks in
   `renderer.coffee` produced it; the holistic review caught it.
5. The plan's header still reads "Not yet approved by Robert". Your "start
   working on it" was taken as approval; the line was left for you.
